## Producer / consumer contract (schema_version 1)

The frontend owns `dashboard/index.html`, `dashboard/styles.css`, and `dashboard/app.js`. The manifest producer owns `dashboard/data/project.json` and `dashboard/data/project.js`; the frontend does **not** fabricate either file.

```json
{
  "schema_version": 1,
  "generated_at": "2026-10-21T00:00:00Z",
  "project": {
    "name": "Wikipedia Historical Network",
    "phase": "planning",
    "languages": ["enwiki", "zhwiki"],
    "storage_format": "Parquet",
    "processing_location_label": "Private processing storage"
  },
  "inventory": {
    "file_count": null,
    "total_bytes": null,
    "source_set_count": null,
    "hosts": [{"label": "Source A", "status": "unverified", "file_count": null, "errors": []}]
  },
  "plans": [{
    "snapshot_id": "enwiki-2026Q3",
    "wiki": "enwiki",
    "target_time": "2026-09-30T23:59:59Z",
    "plan_version": "v1",
    "status": "planned",
    "xml_source": null,
    "sql_source": null,
    "warnings": ["No source has been verified"]
  }],
  "work_items": [{"id": "index", "title": "Verify metadata index", "status": "planned"}],
  "metrics": {}
}
```

This is a **contract example only**, not a shipped project manifest or claim about actual data.

- Required top-level fields: `schema_version`, `generated_at`, `project`, `inventory`, `plans`, `work_items`; `metrics` optional. Unsupported schema or malformed required containers are rejected, not silently rendered as an empty project.
- `generated_at` is a manifest-generation timestamp, **not** a dump or verification timestamp. `target_time` is an ISO timestamp; a quarter is derived from it when the ID does not already include `YYYYQn`.
- `languages`: array of wiki strings. Unknown language/status values are still displayed and filterable. Empty values show “未提供”, never invented defaults.
- Counts may be nonnegative integers or null. Null/missing = unknown; zero = known zero. No number is inferred from planned graph builds.
- `xml_source` and `sql_source`: one selected object or null, not a list. Allowlisted fields only: `{id, date, kind, offset_days, file_count, coverage, status}`. `coverage` is a producer-supplied description string. Signed `offset_days` = source date minus target date; positive means after the target. The frontend does not silently recompute offsets. Source selection is read-only inspection, **not** a source-change or job-start action.
- A plan's `status` represents the producer's planning/index assessment; even `ready` or `complete` is **not** interpreted as proof of a built historical graph. Plan versions sharing a snapshot ID remain separate selectable records.
- Suggested work statuses: `planned`, `blocked`, `running`, `complete`, `verified`, `deferred`; unknown values are preserved. Work-item completion is progress through **declared work items only**, not graph processing percentage or live job telemetry.
- `inventory.hosts`: public-safe labels, status, file counts, error strings. An unavailable host is not silently counted as a verified empty host.
- Optional supported metrics: `index_status` (string), `index_verified_at` (timestamp), `index_record_count` (nonnegative integer), `index_total_count` (nonnegative integer). Record counts describe metadata index records only. Without these fields, the index is explicitly “未报告 / 未验证”. All other metrics are ignored; graph nodes/edges/NGD are not rendered.
- Allowlisting controls what is displayed, not what is downloadable. The producer must sanitize **the entire shipped JSON and JS**, including values: no internal IPs, absolute source paths, device serials, credentials, private hostnames, or raw diagnostic payloads. Host `label`, errors and warnings must be human-reviewed public-safe descriptions. Unknown keys are ignored by the UI but must not be shipped as hidden private data.

## Loading / trust boundary

HTTP(S) mode fetches `data/project.json` with `cache: no-store`. If JSON is missing or inaccessible, it tries the trusted generated `data/project.js`. `file://` loads that local script directly because browser file-fetch restrictions vary. The script must set `window.WHN_DATA = <same sanitized manifest object>;`. Do not use ES modules, a CDN or remote fonts.

A JS manifest executes code: it must be generated by the trusted local producer using JSON serialization, not accepted from an untrusted upload. The UI treats all manifest strings as text (`textContent`), never HTML. Missing data, unavailable files, malformed JSON and invalid schemas produce an explicit non-success state. No sample/fake graph metrics are substituted.

## Preview (local only)

Open `dashboard/index.html` directly for file mode after producer generation. Or, from the repository root:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory dashboard
```

Then open `http://127.0.0.1:8765/`. This is a loopback-only development preview, not a public deployment. The frontend needs no build, package install, Node backend, Docker, or external service. Node is used only by the optional developer tests.

## Acceptance / evidence

Run `python3 -m unittest discover -s tests -p 'test_dashboard*.py' -v`. Tests use Python stdlib and Node for pure data behavior. Synthetic fixtures stay inside tests, not in the shipped dashboard bundle. RED/GREEN execution logs and browser screenshots must stay in private evidence storage outside this repository. Browser checks should cover HTTP, file mode, narrow viewport, keyboard-accessible filters, source inspection, errors, and HTML-like source strings.

Provenance caveats remain visible: metadata inventory is not verified completeness; quarterly plans are not executed graphs; historical XML and SQL source dates can differ; offsets and warnings must be reviewed; wikitext/parser jobs are not implied to be running; NGD is deferred.

## Implemented behavior / handoff

- Chinese UI with English field names; responsive Monitor layout with a filterable plan table and a read-only snapshot inspector.
- Search matches whitespace-separated terms across quarter, ID, wiki, version, target timestamp and status. Language/status filters use the manifest's actual values, including unfamiliar statuses. Result count is a count of **plan versions**, not distinct snapshots or built artifacts.
- The inspector's version selector groups records sharing `snapshot_id` and `wiki`. It can inspect a version outside the current filter and explicitly labels that situation. XML/SQL selection changes only the inspected source panel, not the selected manifest source or processing state.
- Missing counters remain unknown; a supplied zero is displayed as zero. Without optional index metrics the index reads “未报告 / 未验证”. Work progress has no indeterminate/running animation and is hidden when there are no declared work items.
- Only the documented allowlist is projected into UI state. All string content uses text nodes. A producer must still sanitize the entire downloadable manifest, not rely on this projection as a privacy filter.

### Verification performed

Six automated stdlib/Node tests passed after recorded RED → GREEN runs: schema/unknown counts; source and metric allowlists; filter/quarter/version behavior; HTTP/file loader and failure behavior; accessible local markup; actual renderer interactions and focus retention. The renderer tests use a tiny DOM adapter, so they do not replace browser checks.

A real Chromium browser also exercised private, explicitly labeled synthetic test fixtures outside the repository: HTTP JSON, `file://` JS, HTTP JS fallback, malformed JSON (rejected without masking it with fallback data), missing manifest, language/status/search/no-results, version selection, signed offset and source warnings, literal HTML-like text, focus retained after plan activation, and 390px narrow layout. Enabled controls measured at least 44px high; no horizontal overflow occurred at 390px or the desktop viewport. Screenshots and machine-readable observations remain in private SSD evidence storage, **not** in `dashboard/`. One browser screenshot timeout required reconnecting; repeated inspection succeeded.

These checks verify the frontend against its contract, not any later producer-generated manifest or the historical data itself. No shipped project manifests were created by this frontend task. No public deployment, commit, push, parser job or graph build was performed. The temporary loopback test server is stopped after verification.

Design self-audit: 0/10 slop tells in the final Monitor/Inspect composition; no marketing hero, gradient, fake metric, decorative icon cards or remote font. Dense table and restrained green/neutral palette were reviewed in desktop and narrow screenshots.
