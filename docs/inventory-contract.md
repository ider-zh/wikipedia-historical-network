# Private dump inventory contract (v1)

Inventory artifacts live outside this public repository. `tools/inventory.py` emits newline-delimited JSON events; the coordinator compresses full events into `inventory.jsonl.gz` and independently audits persisted records into `summary.json`, `root-coverage.json`, and `errors.json`. Host names, absolute source paths and mount details are private, never dashboard input.

Event types: `discovery` (hostname, mounts, selected roots, exclusions); `root_start`; `file`; `alias` (symlink, not followed); `excluded`; `error`; `root_end` (status, counters, bounds); `host_end`. Every event carries schema_version=1 and host. File records carry path, root, size_bytes, mtime_ns, device, inode, inferred_wikis, inferred_dates, representation, tables, inference_evidence, source_eligible_candidate, truncated, and checksums. Inference is path/filename based, not content validation. `checksums` reports only neighboring manifest availability and `computed=false`; no full hash, CRC or archive integrity is asserted. `truncated` means filename suggests partial/unfinished download; root truncation is separately explicit.

Walk policy: no symlink following; recursively discovered mountpoints become boundaries, even same-device bind mounts. Data mounts plus selected system-disk data roots are independently walked, with nested root ownership preventing duplication. Engines, caches, dependency trees and this project's generated output are explicitly excluded. Candidate files are selected from wiki/history/categorylinks/SQL tokens and wiki-bearing parent context. Opaque archive containers in such context remain candidates but are not source eligible. Archive bodies are not decompressed. Bounds and access failures prevent an unqualified completeness claim.

Coverage audit must compare persisted candidate file counts to each root_end.files; roots missing root_end are incomplete. Summary totals count physical path entries, not unique payloads; device/inode fields permit later hard-link deduplication. Aliases and exclusions have their own records. Multiple runs use separate new output directories; source inputs are never written.

## Consumer details

- `files.jsonl.gz` contains only file records; `inventory.jsonl.gz` retains the complete event protocol. Host labels supplied to the coordinator are directory names; each record's `host` is its observed actual hostname. Read corrected views produced with `inventory_refine.py` when the classifier was refined after collection; `classification.json` links the original inventory and exact classifier code hash without changing source observations.
- Container filenames (`.zip`, `.7z`, `.rar`, `.tar`, compressed tar) are also retained without wiki keywords as `candidate_evidence=unscoped_archive_filename_only`. This catches generic database backups; it is not evidence they contain Wikipedia. Selected bounded archive-header listings are separate evidence, never CRC or payload verification.
- Representation values: `sql`, `sql_schema`, `tabular_dat`, `xml_history`, `xml`, `xml_stub`, `xml_index`, `opaque_archive`, `parquet`, `checksum_manifest`, `unknown`. Only nonpartial SQL/XML candidates receive `source_eligible_candidate=true`; that is filename evidence, not parser or completeness validation.
- Full history requires `history` in the **filename**, never merely its ancestor. Eligibility additionally requires an official wiki-prefixed canonical XML dump basename and an exact XML/compression suffix: derived `ref_`/`tjref_` wrappers, `.txt.gz` derivatives, flow history, fixture directories, `.filepart`/unfinished downloads, stubs and index companions are not direct full-history candidates. Inspect `source_eligibility_reasons`; representation counts alone must never drive source selection. Zero-byte files are blocked in corrected metadata views. Mydumper dot-separated table names are recognized. `page_props` does not prove `page`; schema-only SQL does not prove any table's data is present. A `.sql` file may still be a LOAD DATA loader: retained `.dat` companions need a separate reader/validation step.
- Page-range suffixes `-pSTARTpEND` contain page IDs, not snapshot dates. Strip them before date inference; otherwise a page ID resembling an eight-digit date can incorrectly make a valid shard ambiguous.
- `inferred_dates` contains literal eight-digit date tokens; `inferred_years` separately captures year-only tokens. Year-only or undated containers remain inventoried with unknown snapshot date; do not silently exclude them or promote the year to an exact snapshot. Multiple inferred wikis/dates remain ambiguous, not arbitrarily selected.
- Snapshot grouping can use `(host, parent(path), one inferred wiki, one inferred date, representation)`. SQL page/categorylinks presence must come from data candidate records, not `sql_schema`. Opaque archives, missing dates, zero-size/partial files, and loader ambiguity require blocked/review states, not a source-ready claim.
- `coverage_audited=true` only establishes persisted-file/root-counter agreement, expected root end markers, host end marker, successful process exit and no duplicate paths. `scoped_walk_complete_without_errors` is stricter. Every permission denial and missing root remains in `errors.json` and root coverage; a missing root is not an empty scanned directory.
- `execution.json` preserves the command, privilege flag, UTC bounds, exact scanner SHA-256 (code only) and scanner snapshot. No source payload hashes are calculated. Source CRC/hash verification remains explicitly not performed.

## Re-running

Run `python3 tools/inventory_run.py --host local=local --output NEW_PRIVATE_DIRECTORY` locally. Add `--host LABEL=USER@ADDRESS` for SSH with BatchMode/connection timeout; the scanner is piped through stdin, never copied onto a source filesystem. Pass private `--exclude-path` values for this project's entire output directory, checkout, and separately generated catalog/recovery projects. The optional `--root` restricts scope, `--max-entries`/`--max-seconds` bound each root, and `--sudo` requires separate explicit authorization for metadata-only access. The normal path never uses sudo. Each target gets independently compressed streams, root coverage, exclusions, errors, and summary; the run also contains an aggregate summary.
